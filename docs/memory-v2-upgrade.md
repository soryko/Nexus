# Stage A upgrade and rollback rehearsal

From a checkout containing baseline `4ce3a5b`, run `uv run python tools/rehearse_memory_v2.py`. There are no path arguments: it only creates its own disposable fixtures. The old server is launched from archived pre-v2 Python source using the same interpreter and dependencies; this is not a test of every historical distribution.

1. **Stop all writers and quiesce readers and workers.** Keep the old catalog/store and recovery materials separately. Do not copy an open SQLite file without its WAL. The drill waits for the seed process to exit, takes a SQLite online backup and compares integrity, foreign keys, table counts, row hashes and durable sequence. Keep the original verified v4 backup unchanged.
2. Register a *disposable copy* with `nexus-memory-admin space register`. Registration prepares schema 005 and maps the physical partitions; check IDs against expectations. `store migrate` on the registered ID applies 006. Verify `PRAGMA user_version`, not just exit status. Never enroll two copies of the same store identity as different active stores.
3. Check from new processes: exact bytes, revision, search, idempotent v4 receipt and Git commit/blob evidence; then exercise revision CAS and forget. The actual archived old server must explicitly refuse the newer schema. Do not use it to downgrade the file.
4. For v2 rollback, quiesce both sides and use `store restore` with the registered store ID and a verified, identity-bearing snapshot. It rebinds to that snapshot rather than overwriting the original file. The drill verifies an epoch increment, invalidation of the old ticket, and that a new mount sees the snapshot. A v4 backup has no store UUID: use it separately with the old runtime for a v4 rollback, not as the target of v2 restore.

**Data-loss boundary:** writes after the snapshot, including corrections, forgets and receipts, are absent after restore. Previously forgotten content can become visible again. Reconcile omissions and withdrawals before admitting new readers; keep old grants revoked. Do not blindly replay requests or retire a legacy store as a recovery step. See [owner administration](memory-spaces-admin.md) for command and approval formats.

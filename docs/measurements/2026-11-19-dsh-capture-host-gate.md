# DSH capture pilot: Host activation gate

**Decision: do not enable Save or stage real draft bodies in this profile.** These are read-only observations, not a test of an alternate isolated profile.

- Host inspection exposes browser automation (including trusted clicks), shell and plugin management to the inspected agent. The session is full-access and approval prompts are disabled. The [Action Card implementation](</Users/soko/Repos/deepseek-harness/packages/experimental/action-cards/src/index.ts#L337-L358>) validates a session, action and policy, not an independent human principal. The live approval service needs an open turn and is not an independently verified exact-byte approval path.
- [Tool batch preparation](</Users/soko/Repos/deepseek-harness/packages/core/tools/src/batch.ts#L154-L163>) records the call before plugin validation, and [session export](</Users/soko/Repos/deepseek-harness/packages/session-query/session-log-export/src/archive.ts#L347-L362>) includes the session log as recorded. Redacting the tool result does not keep the arguments private. Existing [prepared retry notices](</Users/soko/Repos/deepseek-harness/.agents/integrations/nexus-memory/hooks.js#L200-L217>) carry payload bytes in session metadata, so they are not private recovery storage.
- Live inspection confirmed that the existing session/event listener is a post-commit feed. It can carry sanitized readiness status but does not itself provide private proposal ingress. No separately enforced human principal or private proposal route was verified. No production action or bypass was attempted. The installed artifact and profile were left unchanged. The [DSH sandbox contract](</Users/soko/Repos/deepseek-harness/packages/sandbox/sandbox/README.md#L162-L170>) explicitly limits its policy to file effects; a separate profile and a file-access preset alone are not evidence of a browser, IPC, process, or credential boundary.

The enclosed synthetic lane can continue independently. The repository’s offline DSH headless text-turn replay was exercised from the DSH checkout with `DSH_SNAPSHOT=replay pnpm run test:snapshot snapshots/session/headless.snapshot.ts -t 'replays text-turn through dsh --profile headless'` (1 passed, 178 filtered/skipped, exit 0). This uses recorded provider responses and temporary state, not the live GUI. It is a baseline, not proof of a capture adapter: the selected replay does not load one. A genuine fresh DSH model trial requires a disposable profile and store with capture disabled and the intended recall binding, exact CLI/provider readiness, and separately witnessed fresh roots. It does not prove web approval isolation.

## Disposable paired model result

The [synthetic harness](<../../benchmarks/dsh_capture/run.py>) seeded six authored facts into real disposable Nexus, called the pure DSH query/context functions, and delivered the intended record on five cases (all rank 1). Fixture rubric scored six ready and zero false positives; it does not show that a normal DSH turn would propose those drafts.

For a separate application check, the lead ran 12 stateless Coeus calls to DeepSeek V4 Pro with reasoning off and temperature requested at zero, one per case/arm. The shared instruction was to answer in one sentence, use any supplied rehearsal records as evidence for the synthetic assignment, and otherwise abstain. Both arms had the same question; only the recall-on arm received the generated DSH context. No tools, answer key or checkout access were supplied. Scoring compared the answer with the fixture's unique assignment and checked abstention manually. Recall-off was 0/6 exact assignments (all abstained); recall-on was 5/6. The deliberately opaque checkpoint prompt is an abstention control, not a fair test of a grounded semantic paraphrase. Its intended record did not surface, and the model answered with an unrelated candidate rather than abstaining. An earlier receipt-only run with the benchmark's unchanged advisory text and no extra clarity about unavailable external verification produced abstention in both arms. This is prompt-sensitive synthetic mechanism evidence, not a fresh DSH Host trial, an organic draft, or a quality benchmark.

## Recovery binding note

Nexus database-location fingerprints describe the resolved path, not a particular database instance or its generation. Even when the path and scope are unchanged, do not use that fingerprint as authorization to retry a prepared operation. A production recovery witness is still unresolved.

The [real stdio delivery tests](<../../tests/tools/test_dsh_capture_delivery.py>) observed one unchanged receipt and revision on identical replay after client/server restart, a sanitized conflict on changed bytes, and that the same call creates a record when no prior send occurred. Fresh and pre-commit backup replacements at the same path had the same location fingerprint; the fixture rejected them by file identity, while an intentional disposable path-only control received a new receipt in each replacement. The fixture oracle does not protect a production check/use window or detect in-place rollback. No Host recovery dispatcher was implemented.

The final targeted command passed 8 tests and 24 subtests. Existing DSH plugin tests passed 57/57. The integrated workflow remains unimplemented: private proposal body ingress, independent human approval, and production recovery binding were not proved. No rollout or production writes were performed.

## Disposable DSH runtime adapter

The [Host probe](<../../benchmarks/dsh_capture/host_probe/README.md>) runs the real DSH AgentLoop, AgentRegistry, and SessionStore with a one-shot mock adapter, disposable state, and no tool schemas. The lead reproduced one authoritative completed root turn (turn 1, sequence 11), one mock stream, no tool calls, a sanitized no-candidate row after completion, and an empty projection on dispose. This fixture does not load the shipped CLI or GUI profile, handle draft bodies, prove private ingress, or exercise human approval or writes.

The expanded probe also observed a genuinely cancelled turn and a completed turn whose user-message ID did not match enrollment. Both published their own authoritative end event, and the adapter explicitly refused them with blank activity. All three runs exposed no tool schemas or calls, and left no disposable directory entries. The combined Python suite now passes 9 tests and 24 subtests; the activity reducer passes 7 Node tests.

**Activation decision: blocked for the inspected profile.** Additional disposable tests do not establish independent human approval or private draft ingress on that profile. Resume implementation when a candidate pilot environment can demonstrate both: (1) approval credentials and surfaces outside agent-reachable browser, process and IPC capabilities; (2) a draft-only path whose synthetic canary is absent from logs, exports and subsequent model context, even on rejection. Before any write-capable retry, also prove backend identity across restart and reject same-path replacement. Enrollment requires separate explicit human authorization. None of these prerequisites authorizes a live write by itself.

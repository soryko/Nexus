# Nexus Memory across agent harnesses

Reviewed 3 November 2026. The Nexus baseline is GitHub `main` at `18d51ac`. The working checkout is the evaluation branch at `76233fe`. The latest tagged release, `v0.1.0a2`, and the Codex adapter at `fad41ba` have different capabilities. Supermemory's inventory was checked at `16ed414`, then traced to the implementations linked below. Upstream plugin behavior is source-reviewed. Nexus observations below distinguish local configuration, disposable protocol tests, and actual host evidence.

**Fix cross-project disclosure and stale automatic delivery first. Then measure eligible tasks and test whether the right memory changes the next action.** Nexus can already preserve a decision across process restarts. Whether the next agent sees it depends on which binary the host starts, which partition it opens, whether a capture happens, and what its prompt hook returns. Supermemory does more of that work inside each host. Its design also shows the cost of getting those defaults wrong. For applications built on the Vercel AI SDK, middleware accepts a stable namespace and conversation ID, can add profile or query context, and saves conversation content by default. [SDK behavior](https://supermemory.ai/docs/integrations/ai-sdk) · [Local and Enterprise architecture](https://supermemory.ai/docs/self-hosting/local-vs-enterprise)

The backend matters to what a user sees next. Supermemory documents a pipeline from a source conversation or document to extracted facts, searchable chunks and a profile with stable and recent context. The next host can request that profile or search by meaning even when the user phrases the question differently. Nexus stores the exact text supplied on a write and searches the current revision lexically. Its revision IDs let a reader check the exact text a prior agent stored and the Git evidence recorded alongside it. Supermemory's published recall scores and Nexus's frozen evaluation use different workloads. They cannot rank the two products for coding tasks. [Supermemory's storage and retrieval model](https://supermemory.ai/docs/concepts/how-it-works) · [Nexus guarantees and evaluation limits](https://github.com/soryko/Nexus/blob/18d51ac1389db5e621d5b5f7d1db90d1620cf269/README.md)

## What the Nexus evidence supports

**Durability and handoff.** Independent MCP processes on main shared exact text and replayed an identical write receipt when database, namespace and actor matched. Changing the database or actor hid the record. A stale revision was rejected. A second unrelated Git checkout sharing all three values could read the record. `--repo` supplies verification context for references. It does not partition ordinary memories. Verified references attest that a path and commit resolved, while applicability still needs checking. These properties are valuable for technical decisions that have to be revised or audited. [Scope guide](https://github.com/soryko/Nexus/blob/18d51ac1389db5e621d5b5f7d1db90d1620cf269/docs/daily-use.md#L164-L187) · [Storage and reference guarantees](https://github.com/soryko/Nexus/blob/18d51ac1389db5e621d5b5f7d1db90d1620cf269/docs/guarantees.md)

**Shared-file behavior.** Returned rows were scoped correctly. In a disposable two-actor fixture, six foreign-actor writes changed the first actor's top hit from `alpha` to `beta` and expired its search cursor. FTS corpus statistics and index generation are database-wide. A client can retry an expired cursor, and deployments needing independent ranking or workload isolation can select separate files. [Search and pagination](https://github.com/soryko/Nexus/blob/18d51ac1389db5e621d5b5f7d1db90d1620cf269/src/nexus_memory/storage/sqlite.py#L1280-L1315)

**Retrieval quality.** Replaying the frozen v2 evaluation reproduced mean current-revision recall of 0.848 across eleven clean queries, with coverage on ten. Two deliberately unanswerable prompts each returned five irrelevant top-five hits. An old-only name missed at every cutoff even though its revision could still be read by ID. The corpus also documents the `retry`/`retries` vocabulary miss. This is evidence for testing term selection, abstention and history cues. The held-out A1 agent comparison covered four tasks and 36 arm-runs. The memory arm won none, lost one and consumed 1.56× the combined baseline input tokens. The turn ceiling truncated 29 of 36 runs, two tasks defeated every arm, and the rendered-notes arm tied the baseline on all four tasks. Neither evaluation compares Nexus with Supermemory on the same harness. [V2 evaluation](https://github.com/soryko/Nexus/blob/18d51ac1389db5e621d5b5f7d1db90d1620cf269/benchmarks/eval/results-v2.md) · [A1 closeout](https://github.com/soryko/Nexus/blob/f5e75cad6321640992fae87c49585e7ffb2b73b2/benchmarks/agent/CLOSEOUT-a1.md)

**Freshness at delivery.** A new disposable test drove the unchanged installed-profile DSH hook against the remote main revision. Search found R1, a writer committed R2, and the hook fetched the pinned R1. Nexus correctly returned R1's content together with `current_revision_id=R2`. DSH injected R1 with `failed=false`. A forget between search and fetch instead yielded zero candidates. Earlier text already admitted to a session remained there. For automatic delivery, require the hit revision, returned revision and current revision to agree at fetch time. Skip a changed record until another search establishes its relevance. Keep explicit historical fetch available. This is a deterministic interleaving, with unknown frequency in actual sessions. Local DSH sources include `.agents/integrations/nexus-memory/hooks.js`, lines 98–146, and its test fixture at `tests/hooks.test.mjs`, lines 269–286. [Nexus get contract](https://github.com/soryko/Nexus/blob/18d51ac1389db5e621d5b5f7d1db90d1620cf269/src/nexus_memory/transport/mcp_server.py#L372-L378) · [Read visibility and retention](https://github.com/soryko/Nexus/blob/18d51ac1389db5e621d5b5f7d1db90d1620cf269/docs/guarantees.md#L29)

**Retrieval alternatives already tested.** In development, stemming raised recall on seven morphology queries from 0.714 to 1.000. History-aware search recovered the registered historical cases but missed storage and latency limits. A relative score cutoff cut irrelevant bytes by 49.35% on frozen v2 and dropped a direct answer. In a separate 24-record fixture, fixed queries ranked refuted advice first or second on three of four tasks. Reuse those fixtures before expanding context or introducing a new index. ## Independent review and revised priorities

Two reviewers received the same anonymized brief without local files, transcripts or the other review. Gemini 4 Argon High answered through agy CLI 1.4.12. The success receipt and CLI log match the same conversation and `gemini-4-argon-high`. Claude Code 2.1.316 returned a successful first-party response with `modelUsage.canonicalModel=claude-opus-5-5`. Two earlier Coeus requests reached their aggregate deadline and produced no reviewer evidence. The opinions below are design judgments. The failure reproductions above came from separate local tests.

| Reviewer | Most useful challenge | How it changes the decision |
| --- | --- | --- |
| Gemini 4 Argon | Count eligible tasks and tool exposure before interpreting inactivity. Compare with memory disabled and consider repo-tracked notes if the service adds cost. Try selecting rare terms from the whole prompt before paying for another index. | Add a positive control for read/write readiness, retain rendered notes as a baseline, and benchmark term selection on the existing frozen fixtures. File-read counts are diagnostic. The primary outcome is the correctness of the next action. |
| Claude Opus 5.5 | Have someone unaware of the treatment establish whether an older decision matters before assigning a task. Count repeated investigation, contradictory edits and rework. An empty-result or sham control can expose the cost of distraction. Add a synthetic secret and an instruction embedded in stored text. | Include unanswerable and refuted cases in a disposable replay. Keep deliberately misleading material out of live user sessions. Measure the proportion of ordinary tasks with any eligible prior decision alongside success on those tasks. |
| Both | Keep scopes explicit, identify builds, expose why recall fired or skipped, and delay hybrid retrieval pending evidence. Both suggested rarity-based term selection and a score floor. | Test each change separately. The eight-word miss supports changing term selection. The small lexical evaluation shows both candidate misses and excess hits. The rejected cutoff above is a concrete reason to require direct-answer preservation before shipping a new abstention rule. |

Neither proposed identity shortcut is sufficient as an authorization boundary. A fork or untrusted checkout can copy a remote URL and share a root commit. A canonical path can be renamed or reused. Prefer an owner-controlled mapping to an opaque local project ID. Reuse Nexus's Git common-directory/worktree checks as inputs to that mapping. Fail closed when provenance is ambiguous. A build stamp should identify the installed artifact, even outside a Git checkout. The package version or the application's current working-tree SHA cannot do that.

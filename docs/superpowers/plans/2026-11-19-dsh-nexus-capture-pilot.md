# DSH Nexus capture pilot: draft, approve, save, reuse

**Status:** plan only. Pilot checkout: /Users/soko/Cerebros/nexus-memory. Implementation home: [the enabled DSH Nexus bundle source](</Users/soko/Repos/deepseek-harness/.agents/integrations/nexus-memory/README.md>). This is a DSH plugin change, not a Nexus schema or retrieval change.

## 1. Goal and baseline

Show one closed loop from ordinary repo work: a completed turn proposes one reusable lesson without a Remember prompt; the user reviews and saves the exact record; a fresh session finds and applies it without having the answer in the prompt.

The [current hook](</Users/soko/Repos/deepseek-harness/.agents/integrations/nexus-memory/hooks.js#L267-L297>) handles explicit Remember requests and a narrow allowlist of successful checks, but ordinary completed turns can skip silently. The earlier [isolated DSH run](</Users/soko/Repos/deepseek-harness/.agents/integrations/nexus-memory/verification/hooks-live.json#L1-L12>) demonstrated an explicit write and later recall. The previous inspection found 57 passing plugin tests and zero active records in the connected scope; it did not establish why that store was empty.

Out of scope: always-on inferred writes, transcript processing, bulk backfill, extra inference requests, cross-project search, embeddings, automatic revision/deletion, and changes to Codex capture policy.

## 2. What the user sees

1. In the opted-in checkout, a completed root turn shows **No durable candidate**, **Draft ready**, or **Blocked** in capture activity. Use reason codes, not excerpts. Do not show a popup for every routine turn.
2. **Draft ready** shows exact body, kind, tags, provenance, checkout, and destination. **Save to Nexus** is the explicit write request; **Dismiss** makes no write. Changing the body requires a new draft and approval. Drafts are not searchable or injected into later model context.
3. After Save, show **Saving**, then **Saved** with memory ID, revision ID, and durable sequence only on a valid receipt. Show **Draft expired — create a new draft** after expiry or Host restart, **Not sent** for a proven pre-dispatch failure, or **Outcome unknown** after an ambiguous dispatch.

Eligible records: decisions, constraints, and verified workarounds. Start with one self-contained body of at most 1,200 UTF-8 bytes and four tags. State what applies, when, and why or what was observed. Require at least one committed, same-turn evidence event (human decision, bounded file read, or actual verification tied to the workaround). A standalone test pass, routine progress, plan-only turn, old recalled text, secrets, PII, and transcripts do not qualify. Source identifiers are generated by the Host. Label provenance as Git-verified only when Nexus actually verified it; a session citation or commit hint is not verification.

## 3. Implementation sequence

**Build order (revised after the AGY review):** Start with **Track 1 — draft signal and recall** in a synthetic/disposable lane using the rubric in B and the controls in §7. Do not build Save or recovery to test this. Then run **Track 2 — deterministic delivery** with a test-only dispatcher, disposable MCP storage, and no UI (C and §7). Finally run **Track 3 — Host authority and opt-in** (A and §6), and integrate the live Save route only if all three tracks pass. Cheap read-only Host discovery may run alongside the earlier tracks. A synthetic bench or a manual explicit save is useful evidence, not completion of the integrated pilot.

### A. Prove the approval route and isolate the checkout

- Reinspect the live Host and its shipped plugin guide. Pin exact tool, event, projection, user-action, and Client slot contracts before coding. Demonstrate that the approval path distinguishes a human UI action from a model tool call, synthetic chat message, or GenUI callback to the model. If no user-only Host route is available, stop at draft-only in test; do not deploy Save.
- Verify the enabled source and baseline without editing the live linked artifact. Implement in an isolated checkout or validation bundle. The [existing MCP connection](</Users/soko/Repos/deepseek-harness/.agents/integrations/nexus-memory/cordis.patch.yml#L5-L34>) is a shared DSH partition, not checkout routing. Use a disposable database in tests; for enrollment use a separate local connection with a pinned canonical checkout, database, namespace and actor. Pilot recall and saving use that same binding. Do not fall back or fan out to the shared store. Test symlink resolution and reject non-enrolled worktrees. Keep the pilot writer off the model tool registry and respect the existing Agent access guards; workers stay read-only.
- Put the pilot behind a single default-off switch, scoped to exactly one checkout. In that checkout, verification commands become evidence, not autonomous writes. Explicit Remember remains a separately authorized path through the pilot binding; it must not create a second draft. Outside the pilot, preserve existing behavior.

### B. Surface one lesson at turn completion

- Reuse the [existing projection](</Users/soko/Repos/deepseek-harness/.agents/integrations/nexus-memory/hooks-core.js#L142-L218>). In opted-in root turns, let the model already handling the turn stage a bounded candidate and evidence event IDs through a proposal-only capability. Give it scoped eligibility guidance. The capability must not choose a destination, browse arbitrary session history, or reach a mutation. V1 adds no separate inference request. Measure whether the ordinary turn actually proposes useful drafts.
- Validate source identity, same-turn membership, allowed event types and checkout on the Host; cap input and reject sensitive data. Do not copy source text to the activity view. Before choosing the proposal interface, test whether DSH records arguments in logs or session exports. If it persists unvalidated draft bodies, use a verified private handoff or do not enable text-bearing proposals on real sessions.
- At a genuine completed user-root turn, promote a validated candidate to **Draft ready**. Ignore failed/cancelled turns, generated continuations, replay, inherited/forked events, workers, and changed checkout. Keep at most one draft per turn and one pending draft per session. Expire after 30 minutes, replacement, or Host restart; approved prepared operations use separate recovery. Keep draft bodies in bounded, owner-scoped Host state and project only sanitized activity. Own queue/effect cleanup and keep capture off the response critical path.

### C. Bind approval to exact bytes and reuse the receipt flow

- Extend the [existing preparation and receipt path](</Users/soko/Repos/deepseek-harness/.agents/integrations/nexus-memory/hooks.js#L151-L225>). The authenticated UI submits an opaque draft ID and version, not body text. The server retrieves the immutable displayed draft and checks owner, session, turn, checkout, config generation, expiry, and payload digest on approval and just before dispatch. Atomically consume approval so a competing Save or Dismiss cannot double-write. Do not treat a model claim that the user approved as authorization.
- Defer cross-draft duplicate detection and merging. Idempotency prevents a repeated approval or retry from writing the same operation twice; it does not make different drafts unique. Freeze the canonical record request and stable idempotency key. Durably persist the approved payload and key before calling record, in access-controlled recovery storage; do not expose retry bytes in ordinary logs, activity, or model context. The existing prepared notice can be reused only if it meets that boundary. Keep sanitized receipt fields after successful finalization.
- A timeout, response loss, or restart after preparation leaves an unresolved operation. Do not retry automatically or replace its key. Pause that session's pilot writes and allow a human-authorized retry of the same payload/key against the same destination. On teardown cancel unsent work and drain or reconcile in-flight work without inventing a receipt.

## 4. Verification gates

| Gate | Required evidence |
| --- | --- |
| Regression and eligibility | Existing integration npm test passes. Add coverage for normal no-candidate turns, routine checks, genuine lessons, forged source IDs, secret and Unicode byte bounds, workers, replay/fork, cancellation, and changed scope. |
| Authority and privacy | Model tools, synthetic messages and another session cannot approve. Refresh never approves. Use a synthetic marker to verify rejected and unapproved body text does not reach Nexus, activity/export, or normal logs. Compare approved preview and exact Nexus get, including intended metadata. |
| Delivery | Dismiss and expiry call no write. Concurrent save/dismiss and double-click produce at most one write. Test a pre-send failure, response loss after commit, and restart after preparation. Same-key retry returns the original receipt and one revision. |
| Real DSH | Use disposable MCP storage, genuine root and worker sessions, and the existing GUI for the user-only approval path. Verify applied bundle/artifact, rendered action, and actual receipt. Confirm shared production scope was unchanged. Do not start a replacement GUI. |
| Reuse | In a fresh session in the same checkout, ask a related question without the answer, record ID, or forced retrieval. Verify the hook surfaced the same record and the agent used it correctly against current sources. In another checkout, auto-recall must not surface it. A lexical miss is a failed recall, not a reason to inject the answer. |

Run the pilot for **10 eligible ordinary turns or one week**, whichever comes first. Report counts by outcome and reason, time to draft/save, added model tokens where measured, and whether a saved fact was reused. **Go/no-go:** one organic approved-and-reused lesson, zero unapproved or cross-scope writes, zero routine checks saved by the pilot. Stop on an authorization or privacy failure, or an unresolved write that cannot be reconciled. No useful drafts means revisit the rubric or turn guidance before adding an extractor. Useful saves without reuse means diagnose recall separately.

## 5. Rollout and rollback

Start with isolated draft-only tests, then approved writes to disposable storage. Enroll the real checkout only after the gates pass and the user authorizes activation. Use Plugin Manager and verify which artifact the running Host loaded, activation warnings, and real UI behavior; do not hand-edit profile state or assume reload. Outside the pilot, behavior must remain unchanged.

To roll back, disable the pilot flag, revoke outstanding approvals, stop new dispatch, and reconcile any prepared operations with their frozen payload and key. Restore the previous artifact if needed and verify a non-pilot session still behaves as before. Preserve the database and committed memories; do not use deletion or restoration as code rollback.

## 6. Independent review: conditions before enabling Save

Coeus / DeepSeek V4 Pro recommended proceeding with conditions. Multi-provider comparison did not establish consensus: the first DeepSeek response was empty at its output limit, OpenRouter returned 401, and a bounded DeepSeek retry returned the substantive review. Apply these gates before implementation leaves the disposable lane:

1. **Approval authority spike.** Name the live Host mechanism, the authenticated principal it checks, and what enforces that agents cannot exercise it. Test the real UI plus negative cases covering model tools, synthetic chat, GenUI callbacks, and the browser privileges actually granted to the pilot agent. A trusted mouse event or authenticated page is insufficient by itself: DSH can dispatch trusted browser clicks. Treat shared OS-account/full-access agents as outside any protection claimed by file permissions alone. If necessary, pilot only with verified capability isolation; otherwise stay draft-only with synthetic data.
2. **Private proposal spike.** Name the body transport and the committed event seam (session identity, turn identity, event sequence, and committed publication; pin exact live fields). Demonstrate with a synthetic marker that unapproved bodies do not persist in normal tool logs, projection output, monitoring, or exports. Do not mistake passing just a draft ID for privacy unless the body ingress is also private. If there is no such transport, demo metadata-only staging with disposable synthetic data and stop before real proposals.
3. **Recovery spike.** Select and document the exact durable Host store, its owning principal, agent access restrictions, and backup/export behavior. Prefer supported Host-owned storage outside the checkout and session log. Retain unresolved approved envelopes until reconciliation; after finalization retain only safe receipt metadata, subject to the verified storage lifecycle. Do not represent this cleanup as secure erasure. Before any real write, demonstrate restart, exact same-key retry, and rejected retry against a different binding. If storage cannot be isolated under the actual pilot capabilities, do not enable Save.

These three proofs are prerequisites, not validation already completed. A draft-only demo does not meet the closed-loop success criterion.

## 7. AGY review: delivery contract and acceptance controls

Coeus counterfactual review and test strategy both returned substantive results through AGY CLI 1.5.11, Gemini 4 Hydrogen High. The former recommends reordering the build; the latter adds failure-path and authority tests. These are two passes by one model, not two independent providers. Together with the earlier DeepSeek review, they agree on holding live Save until authority and privacy are proved. The following choices supersede earlier shorthand in this document.

### Track 1 — Can ordinary work produce something useful?

- Use 5–10 synthetic repo-specific fixtures with facts absent from source files, prompts and general knowledge, plus routine-turn controls. Seed their hand-reviewed forms into disposable Nexus test storage. Independently score whether the draft is useful and whether its evidence actually supports the claim: a valid same-turn event ID alone is not proof. Ask authors to include a natural symptom or trigger term alongside the solution where accurate.
- Pair clean recall-on and recall-off sessions on the same symptom-framed questions with the same model and budget, without leaking answers, IDs, or fixture labels. Score retrieval of the intended ID separately from correct use in the answer. Record per-case misses, false-positive drafts, and overhead. At minimum show a paired case where recall-on finds and applies the intended fact and recall-off cannot supply it. This is a mechanism check, not a quality benchmark. If drafts lack signal or seeded facts cannot be recalled, fix the rubric or lexical framing before integrating Save.

### Track 2 — Is delivery exact, restart-safe, and bound to the same store?

- Split **Draft ready** from approved **Prepared / not sent**, **Dispatch uncertain**, and **Finalized**. Draft TTL and restart expiry apply only before preparation. Dismiss or replacement cannot cancel a prepared operation; the UI must not promise it has. Persist the frozen approval envelope first, then durably mark dispatch uncertain before entering transport; a crash in that narrow window is conservatively ambiguous. A proven-not-sent operation can be finalized locally with zero Nexus calls. No write is reported saved without a validated receipt.
- Expose unresolved operations at checkout/workspace scope after restart, without requiring the original session to exist. Freeze checkout/worktree identity, backend enrollment identity, namespace/actor, key and payload. Path, namespace, repo root, or a mutable HEAD alone are not sufficient backend identity. The disposable test must reject a replaced or restored store at the same path. Choose an identity/generation witness that actually rules out the tested replacements; if the available runtime cannot prove the original destination, block retry rather than adding an undocumented Nexus API or guessing.
- Turning the flag off invalidates drafts and stops new dispatch but leaves read-only recovery status available. Do not assume Nexus offers a read-only receipt-by-key endpoint; an identical record retry is still a write-capable call and may commit if the first attempt never did. Retry only after explicit human authorization on the original verified binding under an enabled recovery policy; if the binding cannot be verified, export only safe metadata and leave it unresolved. Bound unresolved envelopes (start with one per checkout), show age and provide an explicit abandon path that drops retry bytes without claiming that no commit occurred. Keep routine previews, unknowns and audit output redacted.
- Run cross-process replay with identical and altered payloads; crash before preparation, after preparation but before dispatch, during/after dispatch, and after commit before receipt; test concurrent Save/Dismiss, config revocation, flag-off status, destination replacement and restart without the origin session. Confirm exactly one original durable receipt/revision for an identical replay; ambiguous and denied paths never appear as Saved.

### Track 3 — Can the actual pilot profile enforce the boundary?

- Ship no Save to the default full-access profile. A dedicated pilot profile may qualify if agent browser automation and OS/IPC access to the approval or recovery surfaces are effectively restricted, or if a separately verified human principal provides the boundary. Merely moving approval to a native dialog or hiding a command is not proof. Verify actual tool grants and enforcement without changing production permissions.
- Extend the synthetic canary checks to validation failures, exception strings, UI error banners, replay, export and subsequent model context, with sanitized reason codes only. Check explicit Remember never stages a second draft, child evidence never enters a root draft, and unavailable pilot routing never falls back. With slow/unavailable storage, the ordinary turn must finish normally and capture must time out or block without delaying output.

**First execution task:** run the synthetic paired recall and draft-rubric check, plus inventory the approval and body ingress contracts. Leave runtime configuration unchanged. Preserve the original real-pilot criterion: one organically drafted, human-approved fact correctly reused in a fresh session, only after the hard gates pass.

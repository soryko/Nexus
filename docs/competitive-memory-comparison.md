# Competitive memory comparison: Nexus and the DSH Mnemon catalog

**Recommendation:** Keep Nexus as the local system of record for exact, revisioned engineering decisions with Git evidence. Borrow Mnemon's inspectable recall, OpenViking's staged context loading, and other providers' retrieval techniques as optional layers. Do not replace the authority with extraction or advertise better coding outcomes: Nexus's published coding pilot did not show them.

## Scope and runtime evidence

Source review on 2026-11-19: Nexus checkout at `e7beaec`; public dsh-mnemon adapter code pinned at [341968b](https://github.com/omdsh-dev/dsh-mnemon/blob/341968ba89e68056ac15e72f5888711d82b5ce2a/README.md). Upstream product capabilities, the DSH Memory Spaces adapter, and live availability are separate. [dsh-mnemon's provider guide](https://github.com/omdsh-dev/dsh-mnemon/blob/341968ba89e68056ac15e72f5888711d82b5ce2a/docs/en/guides/memory-providers.md) lists nine bundled adapter packages (including Supermemory, outside the requested comparison). Mnemon Native is the prioritized default if its CLI is ready; third-party providers are opt-in. Bundled packages do not include backend services or CLIs. Provider enablement, discovered spaces, active recall spaces, and backend health are different states.

This session's read-only `mnemon_memory_bodies` snapshot returned 16 visible spaces out of 20, five active overall. The visible rows and placement allowlist named only **Mnemon Native and Supermemory**; visible rows showed both provider-enabled and `not-probed`. The other seven providers were **not observed in this View**, not demonstrated disabled host-wide. The web-profile package on disk was `0.5.46+local.codemode.1`; that is not proof that the running Host loaded it or that it matches public source. No provider was enabled, no live write/delete conformance was attempted, and no benchmarks were rerun. The separate live Nexus MCP status reported exact and lexical storage, no derived index, and no repo-verification binding for that instance; the latter is launch configuration, not lack of product support.

## Product vs. DSH adapter

“Exact,” “stored,” and “hard delete” below describe particular adapter operations, not byte-preservation, crash recovery, retry, or physical-erasure guarantees across products. Neither an upstream feature nor its published benchmark transfers automatically to an adapter.

| System | Upstream product | DSH Memory Spaces adapter or Nexus interface |
| --- | --- | --- |
| **Nexus Memory** | [Local SQLite/WAL MCP](../README.md): exact UTF-8 bodies, immutable revisions, optimistic compare-and-set, idempotent receipts, logical tombstones, and current-head BM25 search. Git references are checked on write against a bound checkout; they record commit/path/object ID/type. Exact reference filters narrow results, not rank them. No semantic index in the reviewed build. | Not in the shipped Mnemon provider matrix; separate MCP interface. [Guarantees](guarantees.md) describe transaction/trust limits; [B2a](plans/milestone-b2a.md) defines Git evidence. A verified ref proves object presence at that commit, not source truth, HEAD freshness, ancestry, or a working-tree match. Tombstones hide both current and historic reads through the API, not bytes on disk. |
| **Mnemon Native** | [Mnemon CLI](https://github.com/mnemon-dev/mnemon): local cross-session memory with four typed graphs, intent-aware recall, importance decay and automatic deduplication. | [Driver](https://github.com/omdsh-dev/dsh-mnemon/blob/341968ba89e68056ac15e72f5888711d82b5ce2a/plugins/dsh-mnemon-provider-mnemon-native/src/driver.ts): local CLI recall/browse, entities, typed links/related, soft forget. Catalog calls writes exact, but ordinary remember retains CLI deduplication. Bulk archival uses exact-content reuse plus `import --no-diff` with receipt checks; don't equate ordinary remember or archival with Nexus revision/CAS semantics. |
| **ByteRover** | [Current ByteRover docs](https://docs.byterover.dev/) describe local-first context engineering with a bring-your-own model. The [pinned CLI README](https://github.com/campfirein/byterover-cli/blob/919469b8e10cd8745e87fcca2b77e01635ea09b0/README.md) documents a project context tree, review workflow, Git-like version control for that tree, and optional cloud/team sync for that generation. Those are not validation of objects in the code repo. | [Driver](https://github.com/omdsh-dev/dsh-mnemon/blob/341968ba89e68056ac15e72f5888711d82b5ce2a/plugins/dsh-mnemon-provider-byterover/src/driver.ts): shells out to local `brv` in the knowledge directory for status/query/curate. No full enumeration, graph/related, or forget. Matrix says “async curate”; code waits for CLI success and returns `stored` without an exact memory ID/readback. Treat this as curation success, not a durable exact-record receipt or a promise all newer CLI features work. |
| **Hindsight** | [Vectorize source/docs](https://github.com/vectorize-io/hindsight#core-concepts): banks with retain/recall/reflect, structured facts/entities, and derived observations and mental models; self-hosted and managed options. | [Driver](https://github.com/omdsh-dev/dsh-mnemon/blob/341968ba89e68056ac15e72f5888711d82b5ce2a/plugins/dsh-mnemon-provider-hindsight/src/driver.ts): bank-scoped recall/browse and provider graph/related; remember queues async retain, and forget patches the item to `invalidated`. The adapter does not expose upstream Reflect as a Memory Spaces operation. |
| **Holographic** | The [provider package](https://github.com/omdsh-dev/dsh-mnemon/blob/341968ba89e68056ac15e72f5888711d82b5ce2a/plugins/dsh-mnemon-provider-holographic/README.md) owns this local JSON format. No independent upstream backend verified for **this** provider; don't attach features or results from similarly named projects. | [Driver](https://github.com/omdsh-dev/dsh-mnemon/blob/341968ba89e68056ac15e72f5888711d82b5ce2a/plugins/dsh-mnemon-provider-holographic/src/driver.ts): local structured facts with trust metadata, browse/search, entities/related and removal of facts from the store; saves via temporary file and rename. “Exact fact” is not byte-exact: it trims the body, then deduplicates on that trimmed text. Atomic replacement alone does not establish WAL-style crash or concurrent-writer guarantees. |
| **Honcho** | [Honcho source/docs](https://github.com/plastic-labs/honcho): workspace/peer/session messages, asynchronous reasoning, peer conclusions/representations, hybrid search and natural-language chat; managed or self-hosted. A first-party Cordis integration is separate from this adapter. | [Driver](https://github.com/omdsh-dev/dsh-mnemon/blob/341968ba89e68056ac15e72f5888711d82b5ce2a/plugins/dsh-mnemon-provider-honcho/src/driver.ts), [upstream Conclusions API](https://github.com/plastic-labs/honcho/blob/main/src/routers/conclusions.py): workspace/peer-scoped v3 conclusion search/list and explicit conclusion creation/deletion; no graph/related projection and not the full upstream session or chat surface. An explicit conclusion can be stored without waiting for Honcho to derive one from messages. |
| **Mem0** | [Mem0](https://github.com/mem0ai/mem0) extracts and retrieves scoped user/session/agent memories; [Platform vs OSS](https://github.com/mem0ai/mem0/blob/main/docs/platform/platform-vs-oss.mdx) documents deployment-specific behavior. | [Driver](https://github.com/omdsh-dev/dsh-mnemon/blob/341968ba89e68056ac15e72f5888711d82b5ce2a/plugins/dsh-mnemon-provider-mem0/src/driver.ts): scoped HTTP search/browse and delete, no graph/related. Matrix summarizes async extraction, but only Platform returns `queued`; self-hosted sends `infer: false` and returns `stored`. Neither branch verifies readback in this method. |
| **OpenViking** | [OpenViking](https://github.com/volcengine/OpenViking) exposes `viking://` resources, memory and skills, scoped semantic retrieval, and L0 abstract/L1 overview/L2 full content, plus session-based memory extraction. | [Driver](https://github.com/omdsh-dev/dsh-mnemon/blob/341968ba89e68056ac15e72f5888711d82b5ce2a/plugins/dsh-mnemon-provider-openviking/src/driver.ts), [provider docs](https://github.com/omdsh-dev/dsh-mnemon/blob/341968ba89e68056ac15e72f5888711d82b5ce2a/plugins/dsh-mnemon-provider-openviking/README.md): existing HTTP service, user memory root, semantic find or literal keyword grep, browse/projected nodes without related traversal. A timeout/mismatch may leave a remote file, so inspect the reported URI before retrying; exact readback is not Nexus's atomic receipt/idempotency contract. |
| **RetainDB** | [RetainDB](https://github.com/retaindb/retaindb) distinguishes Local (disk snapshot + append-only journal, coding-agent integrations) from Server/Cloud (HTTP, PostgreSQL/pgvector for self-hosted server). Upstream advertises lexical, vector and graph signals with RRF and reranking. | [Driver](https://github.com/omdsh-dev/dsh-mnemon/blob/341968ba89e68056ac15e72f5888711d82b5ce2a/plugins/dsh-mnemon-provider-retaindb/src/driver.ts): project/user-scoped HTTP search/browse, no graph/related projection, delete. Posts original text with `write_mode: sync` to `/v1/memory`; legacy endpoint fallback drops that field. Adapter returns `stored` without byte readback; fallback success alone does not verify equivalent sync/durability on every deployment. |

## Practical roadmap

1. **Keep the authority stable; expose it better.** Surface compact read receipts in the harness: scope label, memory/revision ID, provenance, and verified commit/path/object/type separate from caller assertions. Make history and exact get explicit actions, not injected transcripts; make enabled/active/health separate labels. If integrating with DSH, start with read-only browse/search/get against one explicitly bound Nexus service. Add writes only after proving the provider contract carries the identical idempotency payload, expected revision, and durable receipt end to end; never silently route to another provider or report `queued` as committed.
2. **Improve cheap candidate generation before adding models.** Test an opt-in morphological/identifier-aware lexical lane against baseline (word forms, paths, symbol fragments) and evidence-ID-only budgeted packing; keep exact ID reads and byte-exact Git filtering unchanged. If cheap improvements leave no-overlap misses, try a local semantic candidate index as a rebuildable projection keyed by scoped memory/revision. Rehydrate each hit from current authoritative state; reject stale, foreign and tombstoned hits. Semantic scores must not become confidence or provenance; keep BM25 as fallback and record which lane retrieved each result. Do not move model calls or network I/O into the write transaction.
3. **Separate derived context and capture from committed facts.** Try OpenViking-style short previews with on-demand full revision and Mnemon-style recall inspection before building graph or reflection. Put summaries, proposed entity links, and extracted notes in an opt-in, versioned derived/candidate lane. Retain explicit promotion; machine interpretation, Git object presence, and factual correctness have distinct labels. Do not use semantic dedup to overwrite distinct decisions, or turn Git sync/path tags into verified repository evidence.
4. **Gate claims and rollout with two experiments.** First use exact/Git conformance: byte preservation (Unicode/whitespace), same-key crash/timeout replay and changed-payload conflict, stale-head races, checkout identity/worktree/clone behavior, invalid refs fail closed, revision and tombstone isolation even with stale indexes. Then pre-register held-out coding tasks (cross-session handoff, contradictory decisions at different commits, wrong-worktree traps, known/unknown recall). Compare no memory, bounded rendered notes, current Nexus, improved Nexus, and Mnemon Native; add ByteRover or a hosted system only in a separately labeled arm where policy and matching budget permit. Hold tasks, agent/model, context caps, ingestion inputs and judging fixed where possible; report differing adapter/native paths, task success, exact evidence/citation correctness, false injections, read/write latency, tokens and cost. Require zero conformance regressions and a predeclared improvement over rendered notes at a bounded cost before enabling richer recall by default. Publish failures, not just aggregate scores.
